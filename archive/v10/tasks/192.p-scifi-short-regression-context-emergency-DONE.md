## 根因与修复

### 1. Task 192 Ch100 rebuild failure policy

Task 192 的 xuanhuan clean Ch100 source rebuild 不能使用历史诊断默认的 `isolate`，否则 failed chapter 会污染 clean source 样本。

修复：

- `scripts/run_172b_ch100_climb.py` 新增 `ON_FAILURE`。
- `RUN_ID=192` 且未显式设置 `ON_FAILURE` 时默认 `abort`。
- 历史 `172b/172c` 默认仍为 `isolate`。
- `abort/retry` 策略下若 `ProjectRunResult.chapters_failed` 非空，分段 climb 立即停止并记录 `chapter_failed_abort`。

### 2. scifi 短窗口 regression failure

冻结失败现场显示 scifi end10 失败不是 `run_172b_ch100_climb.py` 直接调用路径造成；回归命令走 `scripts/run_172a7_genre_validation.py`。实际 P1 根因是 Ch8 `SettlementExtractor` 结构化 JSON 输出被默认 `max_tokens=4096` 截断，导致 settlement parse failure，随后 ContextEmergency + failed chapter 组合触发 auto halt。

修复：

- `src/songyan/agents/settlement_extractor/__init__.py` 新增 `STRUCTURED_SETTLEMENT_MAX_TOKENS = 8192`。
- `extract_settlement()` 调用 `call_llm(..., max_tokens=8192, max_retries=2)`。
- `tests/test_settlement_extractor.py` 补断言，锁定 settlement 结构化输出预算。
