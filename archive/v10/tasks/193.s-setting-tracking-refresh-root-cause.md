## 背景

Task 192 xuanhuan Ch100→Ch200 共触发 23 次连续性硬门（`health_low_p1_halt` ×13、segment audit `critical_orphans` ×6、`health_low_streak_halt` ×4），以每 5-6 章一次的密度贯穿 Ch75-Ch198，全部用"版本化 continuity patch + `promote_to_active` 刷 tracking + resolve marks"的数据级手法绕过，**机制级修复 0 次**。wuxia 已重演同类问题（193.q Ch117 `blood_abyss.reverse_practice`）。按密度外推，wuxia/urban 剩余约 200 章还将触发 30-40 次同类人工介入。

已锁定的机制事实：

- `SettingTrackingRepository.promote_to_active()`（刷新 `last_mentioned_chapter`）的**唯一生产调用点**是 `src/songyan/workflows/_input_side_governance.py:245`。
- 该路径的匹配源是 `_promotion_evidence_text(settlement)`——**settlement 文本，不是章节正文**；匹配方式为候选 setting 的 terms 对 evidence 做 exact/substring 词面匹配（`_input_side_governance.py:225-246`）。
- 典型症状（192.v 原文）："Ch93 正文已明确提到'与守灵的交易换来的，专克你们这些守门者'，但 `setting_tracking` 中 … 的 `last_mentioned_chapter` 仍停在 Ch89。"
- 同一批 key 反复孤儿化：`lingyuan_quan_first_form`（Ch81/105/150）、`mother_descendant`（Ch120/138/168/192）、`self.as_door`（Ch162/168/180/186/192）。

由此形成工作假设：**正文提及从不直接刷新 tracking，必须经"settlement 提取 → evidence 文本 → 词面匹配"两道中转，任何一道漏损都会产生漏报。** 本任务先用冻结证据证实/证伪并量化各分支占比，再决定修不修、修哪层。

对每个案例、每个漏报章节，只读回放以下事实并归类：

- **分支 1（匹配层漏报）**：该章 settlement evidence text 中包含该 setting 的提及，但 `_candidate_terms` exact/substring 匹配失败（改写/称谓变化/分词差异）→ 匹配层 bug。
- **分支 2（提取层漏报）**：settlement 结构化输出根本没有提取该 mention（LLM 未报或提取契约未要求回传既有设定提及）→ 提取契约/prompt 层问题。
- **分支 3（过滤层漏报）**：候选集在 `_input_side_governance.py:220-221` 的过滤条件（如 `introduced_in_chapter < chapter_number`、status 白名单）处被提前排除 → 过滤逻辑 bug。

产出：每案例分支归类 + 全样本分支占比 + 修复面评估，落盘诊断报告。

## Phase B 决策门

- 分支 1/3 为主（匹配/过滤/写入层，改动有界）→ 进入 Phase C 修复。
- 分支 2 为主（提取契约/prompt 卡变更，属 prompt 注入类改动）→ **默认不在 V10 内修**，记录决策并路由 V11 单独立项；本任务以诊断报告 + 决策记录收口。
- 混合分支 → 按占比评估：有界层修复能消除 ≥70% 漏报则修有界层，其余记录遗留；否则整体路由 V11。

## Phase C（条件触发，仅当决策门放行）

- 修复匹配/过滤/写入层缺陷；保持 tracking 刷新语义对历史库只读复算可解释。
- 单元测试覆盖：正文提及经 settlement 中转后正确刷新、paraphrase 场景、过滤边界。
- E 组回归：scifi 短窗口 end10 回归；xuanhuan 冻结库只读复跑 five-gate @200 / segment audit @200 确认历史结论不漂移。
