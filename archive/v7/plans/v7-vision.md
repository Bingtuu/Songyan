# V7 构想：从叙事骨架到完整线索经济 + 满 Ch300 验证

> 前置：V6 已装上**最小叙事骨架（全书大纲 / 弧规划 / 线索追踪 MVP）**、建立长篇质量度量体系、缓解 orphan 治理端缺陷、补足无人值守长跑底盘，并取得真实 Ch1-Ch150 证据。
> 本文是方向性构想，非可执行规划。具体 Task 拆分待 V6 验收数据出炉后再定。
> 编写时间：2026-06-30（第二轮修订：与 V6 叙事骨架对齐）。论证基础：`docs/300-chapter-gap-analysis.md`、`docs/v6-plan.md`。

---

## 1. V7 要回答的核心问题

V6 让系统"有骨架、看得见质量、能可靠地跑到 Ch150"；V7 要回答：

> **当骨架已经存在、度量已经能说真话，我们能不能让系统自己把质量维持在高位，一路稳到 Ch300？**

这是从"骨架 MVP + 观测质量"到"完整线索经济 + 保证质量"的跃迁。V7 的本质是**把 V6 的最小骨架长成完整的自驱叙事系统，并闭合三个开放环**：
0. 叙事骨架从"静态注入 + 被动追踪"升级为 **plan→generate→re-plan 闭环**（弧规划随剧情演进动态调整）；
1. 文学质量从"诊断"到"驱动修复"；
2. 长程伏笔从"被动遗忘"到"主动兑现调度"；
3. 质量门禁从"观测降级"到"可生产的 enforce"。

---

## 2. 四大方向

### 方向零：叙事骨架的动态闭环（V6 MVP 的升级）

**现状（V6 结束时）**：骨架存在、能自顶向下派生章节目标、线索能被追踪，但仍是**静态规划**——大纲/弧规划在项目创建时定稿，不随实际生成的剧情演进而调整，也没有"重规划"机制。

**V7 构想**：
- 引入 **plan→generate→re-plan 闭环**：弧结束后，基于实际生成内容（ArcSummary + 线索状态）评估"弧目标是否达成、哪些线索偏离原规划"，必要时调整后续弧规划。
- 让骨架成为**活的**：既约束生成，又被生成反馈修正，而非一份写死的大纲。
- 边界守则：重规划必须可审计、可回滚，且保留"用户锁定主线不被自动改写"的开关。

### 方向一：文学质量闭环（从诊断到修复）

**现状（V6 结束时）**：LiteraryAuditor 的维度已入库、可看趋势，但仍只诊断、不驱动改写。

**V7 构想**：
- 当文学趋势检出持续退化（如连续 N 章 character_autonomy 走低），触发**针对性修订路径**——不是整章重写，而是定向补强人物主动性/削减概念空转。
- 难点：文学质量是主观、半开放问题，"自动判定好不好看"本身没有成熟方法。V7 应**先小范围验证"文学修订真的让分回升且不引入新问题"**，再决定是否纳入主流程。
- 边界守则：宁可"诊断 + 告警 + 人工介入点"，也不要为追求全自动而引入不可控的改写循环。

### 方向二：长程伏笔的主动调度（V6 线索追踪的升级）

**现状（V6 结束时）**：PlotThread / 弧级伏笔兑现率已可追踪和度量，但兑现仍主要靠 LLM 当场判断 + 事后审计，规划阶段未主动调度。

**V7 构想**：
- 引入**伏笔兑现调度**：在章节规划阶段，把"临近兑现窗口的长程伏笔 / 本弧应收束的线索"作为本章/本弧的候选主题主动喂入（建立在 V6 的 PlotThread 之上）。
- 区分伏笔类型：短线（弧内兑现）vs 主线长线（跨数十章），后者不适用"逾期归档"一刀切，需要专门的生命周期与提醒节奏。
- 度量闭环：弧级伏笔兑现率（V6 已建立）成为 V7 调度的一等驱动信号。

### 方向三：可生产的 enforce 门禁

**现状**：enforce 模式下首个 P1>0 即 halt，`quality_gate_fail_streak` always-on，导致 enforce 不可生产用，系统实际是"观测并降级接受"。

**V7 构想**：
- 基于 V6 的质量债账本与 orphan 绝对量度量，把 enforce 门禁**自适应化**：用相对趋势/异常因子而非绝对阈值触发 halt。
- 让 enforce 成为"在质量真正失控时才暂停、而非在正常波动时误伤"的可信机制。
- 终态：enforce 可作为默认或一键启用的"质量保证"模式，而不只是观测。

## 3. 满 Ch300 渐进验证

V7 的验证不是"一次跑 300 章"，而是**渐进式爬坡**，每一级都取得真实证据再进下一级。

> **阈值占位说明**：下表"关键判据"目前是**方向性占位，非可判定验收标准**。V7 的具体数字（斜率上限、兑现率下限、质量债占比等）必须等 V6 阶段 D 产出 Ch150 基线后，沿用 `docs/v6-plan.md` §1.4 的 T1–T8 口径标定并冻结，再写入 V7 正式规划。在此之前不得作为通过/不通过依据。

| 级别 | 目标 | 关键判据（占位，待 V6 基线标定） |
|------|------|------------------------|
| Ch150 | V6 已达，作为 V7 起点基线 | 五类长期指标（orphan 绝对量 / 新 critical 产生速率 / 质量债 / 文学趋势 / 弧级兑现率）全程可读且未触 V6 红线；主线可追踪 |
| Ch200 | V7 第一里程碑（README 既定现实目标） | orphan 斜率收敛、质量债占比可控、弧级伏笔兑现率达标（具体阈值待标定） |
| Ch250 | 过渡验证 | 长线伏笔出现真实跨数十章兑现案例（≥1 条主线伏笔跨度 ≥50 章并兑现） |
| Ch300 | V7 终态目标 | 事实库可信 + 文学质量趋势平稳（不触 T3 红线）+ enforce 可生产（具体阈值待标定） |

**判据原则（沿用 README 长期目标口径）**：300 章目标不只看章节数，而看**长篇运行后的事实源质量**——角色状态可信、设定正确回收、伏笔持续可追踪、数字有正文证据；以及 V7 新增的**文学质量不随长度衰减**。

## 4. 可选方向：题材泛化

仅当产品目标包含"换题材也能高质量长跑"时纳入 V7（否则可独立成 V8 或不做）。

需解决 `docs/300-chapter-gap-analysis.md` §7 列出的半硬编码：
- settlement 设定簇 canonical 词表外置为 genre 配置；
- 数值 telemetry/evidence allowlist 由 genre JSON 注入而非写死；
- 主角名等项目专属信息从代码移到 project 档案。

完成后，在非科幻题材（玄幻/都市）上跑一遍 Ch1-Ch100，验证数值结算与设定回收不重新爆发 whack-a-mole。

---

## 5. V7 不变的工程纪律

继承 V5/V6 的不可违背约束：
- SQLite 唯一事实源；LangGraph state 只存 ID；
- 证据驱动结算（source_quote / 公式闭合），不写入无证据数据；
- 版本不可覆盖；
- 不为追求"全自动"而引入不可控循环——开放问题优先保留人工介入点。

---

## 6. 阶段全景

| 阶段 | 一句话 | 章节验证深度 |
|------|--------|--------------|
| V5 | 长篇生成主链路工程验收 + 事实库治理起步 | Ch150（旧管线）/ Ch30（治理管线） |
| V6 | 装上最小叙事骨架 + 看得见质量 + 能可靠地跑 | Ch100-150（骨架管线） |
| **V7** | **骨架长成完整线索经济，让它"自己把质量维持在高位，稳到 Ch300"** | **Ch200 → Ch300 渐进** |

> 一句话总结分工：**V6 给它"骨架 + 眼睛 + 体力"，V7 让它"自己把故事讲好并稳到 300 章"。** 把 300 章压进单个阶段，风险是重演"用一个绿色指标掩盖未解决的结构债"。
