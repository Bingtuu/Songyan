## Goal

检测 `run-bba292da` 中暴露的**跨章时间线矛盾**（Ch75 最重：倒计时/时间戳前后不一致）：建立"倒计时数值、时间戳、相对日期"跨章一致性检测，作为**诊断项入 report**（先观测、不阻塞 accept），为后续（是否升级阻塞、是否纳入 T9）积累真实数据。

## Context

设计核实（2026-07-04，创建前对主干代码核对）：

- **矛盾形态**：Ch75 等章出现"倒计时 X 小时"在相邻章不自洽（如上一章"还剩 3 天"，下一章突然"还剩 5 天"）、时间戳/日期回跳、相对时序矛盾。这类缺陷**跨章**，句子级/单章审计（RuleAuditor / LLMAuditor 都是单章）**结构性看不见**。
- **无现成跨章时间检测**：现有审计器均以单章 content 为输入。跨章一致性需要**回读前若干章的时间信息**——这与 Task 147 文学趋势"按章节范围回读"、`render_stage_a_metrics` 逐章度量是同类"跨章读 DB"能力，但**时间信息目前未被结构化抽取/入库**。
- **保守定位——先诊断不阻塞**：时间线矛盾判定有**误报风险**（叙事可能有合法闪回、多线并行、主观时间感），全自动阻塞会误伤。按 V7 决策边界"文学修复保守 + 诊断告警 + 人工介入点"，本 Task **只做检测 + 入 report 诊断**，是否升级为 accept 阻塞或纳入 T9 红线，待 164/165 用实测数据评估。
- **抽取口径**：优先抽取**确定性强、误报低**的时间信号——显式倒计时数值（"还剩 N 天/小时"）、绝对日期/时间戳、明确的相对时序词（"三天后""次日"）。模糊的主观时间感（"仿佛过了很久"）不纳入。

**边界**：这是"跨章时间信息抽取 + 矛盾诊断"的确定性检测，**不引入 LLM 判断时间逻辑**（可用正则/规则抽取时间信号）。**不修复**矛盾（不改写正文），只诊断告警。

## In Scope（必须完成）

- [ ] **时间信号抽取**：从章节正文抽取确定性时间信号——显式倒计时数值、绝对日期/时间戳、明确相对时序词。抽取为结构化记录（章号 + 信号类型 + 值 + source_quote/定位），可入库或运行时派生（参照 continuity 逐章度量的持久化方式，避免假设已有列）。
- [ ] **跨章矛盾判定**：对相邻/近邻章的时间信号做一致性判定——倒计时应单调递减且与章间间隔自洽、日期不无故回跳、相对时序不矛盾。判定规则确定、可解释、可单测。
- [ ] **入 report 诊断**：矛盾结果作为**诊断项**进入度量/report（`songyan report` 或 `songyan metrics` 的相应段），含矛盾章对 + 信号值 + 定位。**不阻塞 accept**（本 Task 明确只观测）。
- [ ] **误报控制**：以 `run-bba292da`（尤其 Ch75）真实样本标定抽取与判定规则，确保能抓住真矛盾、同时对合法闪回/多线不产生大量误报；记录已知误报形态。

## Out of Scope（明确不做）

- 不做元标记清洗（Task 160）、段落去重（Task 161）、概念预算（Task 163）。
- **不阻塞 accept、不修复矛盾**（不改写正文）——本 Task 只诊断。是否升级阻塞留 164/165 评估。
- 不抽取模糊主观时间感；不引入 LLM 判断时间逻辑（保持规则/正则抽取）。
- 不做时间线的自动纠正/重规划（那涉及生成侧，属 X 阶段自驱范畴，且高风险）。
