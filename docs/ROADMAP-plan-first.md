## 目标

约 90 天内证明一件事：**plan-first 能把跨章真错误召回做到可用**。可用的尺子是霞飞路这一类错误上 **召回 ≥4/5**。

### B. 最小对照：人批事实卡 → 写 3 章 → 窄验证

**第一刀（随本文件合入）：事实卡 schema。** ADR-0001 的五类记录可以创建、读回、再写进 SQLite，带稳定 ID。`approval_status` 把 `pending` 和 plan|human 已批准的 canon 行分开。这一刀不写霞飞路正文，不接窄检查，不改 SettlementExtractor 的权威路径，也不把抽取结果自动吸进这些表。

**第二刀（随本文件之后的切片）：批准卡 + 三项窄检查。** `project_id=xiafei-jiuan` 的 ch1–3 卡已批准入库。必须提及、主张核验、类型化属性比较在 `src/songyan/plan_checks/`，用 v4 正文做了 fixture 对照（见 [xiafei-plan-checks.md](xiafei-plan-checks.md)）。还没有接到写章流水线，也没有重跑正文。成功门不变，留到重跑那一刀。

**下一刀：** 把这三项窄检查接到章节流水线的只读门上（只读已批准 plan 卡；不改 SettlementExtractor 权威，不把抽取吸进 canon）。先不重跑 ch1–3。窄验证仍只做下面三件事。

1. **必须提及**：本章计划点名的证物、伤情、时间锚，生成后逐条核对是否出现。
2. **主张核验**：事件卡上的每条主张，对照正文段落，判支持 / 矛盾 / 未提及，并附引文。
3. **类型化属性**：方向、数量、时间锚、归属等能代码比较的字段做代码比较。

正文里新冒出来的事实进待审队列。人批准之后才可以进 canon。

成功门（三条都要有记录，缺一条不算过）：

- 召回 **≥4/5**。分母是 v4 那 5 条人工真错误所属的类：证物属性漂移、机制方向、证据遗漏、时代时间线。拦截或不发生都算召回；要写出每条的归类，不能只给一个总分。
- 人工 **≤10 分钟/章**（批卡、看核验、决定待审项）。
- 成本说得清：单章用户口径与 v1 同量级（v1 三章合计 ≈¥1.37；单章 ¥0.246–¥0.766）。单章超过 v1 第 3 章（含重跑）一个数量级就停，先报告，不加检查项。

可选、单独成一次切片：检查器改用 deepseek-reasoner 的消融，只看召回和成本增量。推理模型只用在窄判断上，不用来通读找错。

### C. 第二体裁 3 章，不加题材专用规则

B 过了之后，另选一个体裁跑 3 章。调研报告建议仙侠或言情；开跑前由 owner 指定一个。代码和检查规则保持与 B 相同，不为这个体裁加专用规则。

成功门与 B 相同：召回 ≥4/5（用该体裁上人事先标出的跨章真错误，不把霞飞路的 5 条硬套过来）、人工 ≤10 分钟/章、成本同量级。

若失败：停止加规则。退到薄封装——**人维护事实圣经，AI 按圣经写**。把失败记进实验笔记，作为「需要更多人在环」的证据，不把它补成一套新的题材检查器。

## 非目标

这些不做，也不要在每日切片里顺手做：

- 开放式全书 / 多章「找矛盾」。
- 把正文抽取到的事实自动吸收进 canon。
- 继续把「抽取 → 比对 → 打补丁」当主路径。
- 为每个新题材加专用检查规则来追召回。
- 用摘要链代替结构化状态。
- 写完《规则年代》或任何 300 章规模的正文。
- 在 A 的 bug 切片里改写规划 / 写作 / 审查管线。
- 在事实卡 schema 这一刀里改写规划 / 写作 / 审查图节点，或让 SettlementExtractor 停止写现有结算库。

## 90 天怎样算证明了

A 完成，并且 B 的三道门有记录。C 要么在不加题材规则的情况下过同一组门，要么写下薄封装退路。两条都算这条路线有了结论。结论可以是「plan-first 够用」，也可以是「必须更多人在环」；不能是「再加一批检查规则继续抽」。
