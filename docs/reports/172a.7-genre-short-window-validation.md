## 未达标项 → 路由 172a.p

**overdue foreshadowing = 28（目标 < 5）**：这是 V8 验收 S 维度，**未通过**。

根因（已定位）：
- xuanhuan 每章密集埋设伏笔（settlement 日志 `foreshadowings_count=29`），`expected_resolve_chapter` 由 LLM 在结算时选定，horizon 偏短。
- overdue 计数逻辑（`_scanners._find_overdue_foreshadowings`）= `expected_resolve_chapter < 当前章 且 status != resolved`，与本报告度量一致，28 是真实值。
- `GenreRuntimeProfile.foreshadowing_evaporation`（172a.6）只影响**注入排序的紧迫性加权**，不改变**埋设 horizon**——因此运行时参数化无法压下 overdue。

**结论**：overdue 是伏笔调度（plant-time horizon / 主动回收）问题，超出 172a"运行时参数解耦"范围（改 horizon 需动结算 prompt，属 V8 明确不做的 prompt 工程，或需新调度策略）。**按规划路由到 `172a.p` 撞墙定点修复**，不在 172a 内以放宽阈值或改 prompt 的方式强行达标（違反質量同標 + 不做 prompt 工程纪律）。
