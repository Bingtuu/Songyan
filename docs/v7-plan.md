## 0. 规划依据：Task 159 暴露的真实缺口

V6 证明了系统"有骨架、看得见质量、能可靠跑到 Ch150"，但对 `run-bba292da` 全部 150 章正文的人工通读暴露了 V6 度量掩盖的**篇章级质量债**：

| 缺陷 | 实测范围 | 性质 | 根因 |
|------|----------|------|------|
| **元标记 `### Scene N` 泄漏进正文** | 52/150 章 | 可读性硬伤 | Writer 场景标记未清理；`detect_markdown_scene_titles` 正则要求数字（`Scene \d+`），漏掉字面 `Scene N`；且仅"观测"不阻塞 accept |
| **整段落逐字重复 + 时间线矛盾** | 19/150 章（Ch75 最重） | 连贯性硬伤 | 修订/合并环节把不同版本片段拼接后未去重 |
| **概念通胀（conceptual_grounding 7.12→6.02）** | 中后段持续退化 | 世界观落地不足 | 每章造新概念但不落地；"不是X—是Y"句式空转 |
| **主线收束乏力** | 结尾 Ch150 仍在开新坑 | 叙事骨架静态 | 无 plan→re-plan 闭环；伏笔无主动兑现调度 |
| **句子级度量虚高** | literary_quality 7.46 但读感割裂 | 度量盲区 | harness 是单章句子级，看不到篇章级缺陷 |

**V7 的第一性任务**：先把这些"读者一眼可见"的篇章级缺陷治理掉（治标但高收益），再谈自驱与爬坡。**质量修复优先**（本轮已确认）。

## 1. V7 的定位与边界

### 1.1 一句话目标

> **V7 让系统"自己把质量维持在高位"——先修复 V6 暴露的篇章级质量债（文本洁净、去重、概念落地），再闭合文学质量、伏笔调度、enforce 门禁三个开放环，最终渐进验证到 Ch300。**

### 1.2 四个决策边界（2026-07-04 确认）

1. **质量修复优先**：先修 159 暴露的篇章级缺陷 + 文学质量闭环，再做长程爬坡。
2. **文学修复保守**：以**确定性工程修复**（清洗元标记、段落去重、概念预算约束）+ **诊断告警 + 人工介入点**为主；**不做全自动 LLM 改写闭环**（半开放问题，风险高）。可在小范围验证"定向修订确实让分回升且不引入新问题"后再评估是否纳入主流程。
3. **渐进爬坡 Ch200→Ch300**：Ch150 基线 → Ch200 → Ch250 → Ch300，每级取真实证据再进下一级。
4. **不纳入题材泛化**：V7 专注科幻单题材把质量做到 Ch300；genre 配置化划归可选/V8。

### 1.3 V7 不做（明确划界）

| 项 | 归属 |
|----|------|
| 全自动文学质量 LLM 改写闭环（不止诊断、能无人驱动改写并保证不劣化） | V7 只做小范围验证，不纳入主流程（除非验证充分） |
| 题材泛化（genre 配置化 + 非科幻验证） | 可选 / V8 |
| 多项目并发 / 分布式长跑 | 不做 |

| 维度 | 判据 |

## 5. V7 不变的工程纪律（继承 V5/V6）

- SQLite 唯一事实源；LangGraph state 只存 ID；
- 证据驱动结算（source_quote / 公式闭合），不写入无证据数据；
- 版本不可覆盖（每次生成/修订新建 `chapter_versions`）；
- 不为追求"全自动"引入不可控循环——文学修复等开放问题优先保留诊断+人工介入点；
- 纯验证 Task 不改治理代码；缺陷另开修复 Task；
- 阶段出口未达标不进入下一阶段。
