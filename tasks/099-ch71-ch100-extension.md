# Task 098: Ch71-Ch100 扩展验证（100 章可行性证明）

> **Phase**: V4.0 Phase B — 扩展验证
> **优先级**: P0
> **依赖**: Task 097（Ch51-Ch70 压力测试通过）
> **预计工作量**: 大（4-5 天）

---

## Goal

验证系统在 Ch71-Ch100 区间的稳定性，证明**100 章全自动生成**的可行性。这是 V4.0 的核心目标之一。

---

## Context

### 为什么 Ch71-Ch100 是终极考验

| 因素 | Ch70 状态 | Ch100 预判 |
|------|----------|-----------|
| 总 settings | 427 | **~600** |
| Active settings | 91 | **~100** |
| 向量库 chunks | 917 | **~1300** |
| 总 foreshadowings | 211 | **~300** |
| 累计摘要数 | 69 | **99** |

这是系统首次运行到 **100 章**，没有任何历史数据可参考。

### V4.0 承诺

> **"支撑 100+ 章稳定生成"**

本 Task 是验证这一承诺的终极测试。

---

## In Scope（必须完成）

### 1. 端到端验证 Ch71-Ch100

使用断点续跑：

```bash
# 从 Ch70 的 DB 续跑
python scripts/task_095_runner.py \
    --resume \
    --db-path evals/output/task_097_scifi_webnovel/test.db \
    --start 71 \
    --end 100
```

配置：
- 种子：`evals/seeds/scifi_webnovel.json`
- 输出目录：`evals/output/task_098_scifi_webnovel/`
- 模式：webnovel
- 预计总耗时：**~3 小时**（30 章 × 6 分钟）

### 2. 扩展指标收集

除标准指标外，新增：

| 指标 | 说明 |
|------|------|
| 累计生成时间 | 100 章总耗时 |
| 累计成本 | 总 LLM 调用 × 单价 |
| 每章平均耗时 | 是否随章节增加而增长 |
| 失败/回退率 | 需要 rewrite 的章节比例 |
| Arc Summary 生成 | Ch70 触发一次，Ch100 是否触发 |
| 数据库大小 | `test.db` 文件大小增长曲线 |

### 3. 关键拐点监控

特别关注以下章节节点：

| 节点 | 关注点 |
|------|--------|
| Ch75 | 向量库突破 1000 chunks，检索延迟是否增加 |
| Ch80 | Active settings 是否突破 100 |
| Ch85 | Token budget 是否突破 1.2 |
| Ch90 | Health score 是否跌破 1.0 |
| Ch95 | 生成时间是否显著增加（> 8 分钟/章） |
| Ch100 | 整体稳定性总结 |

## 验收标准（Acceptance Criteria）

- [ ] Ch71-Ch100 端到端跑通，**0 失败**（允许 ≤1 章因 API 错误失败）
- [ ] 总章节数达到 **100 章**（Ch1-Ch100，其中 Ch1 为种子）
- [ ] Ch71-Ch100 字数达标率 **> 60%**
- [ ] Ch71-Ch100 budget_used 平均 **< 1.3**
- [ ] Ch71-Ch100 health_score 平均 **≥ 2.5**
- [ ] Ch71-Ch100 token_budget 平均 **< 1.3**
- [ ] 生成时间未显著恶化（Ch100 与 Ch70 单章耗时差异 < 50%）
- [ ] 生成 `evals/output/task_098_scifi_webnovel/report.md` — 100 章综合报告
- [ ] 生成了 `tasks/098-ch71-ch100-extension-DONE.md`

---

## 失败处理策略

| 情况 | 处理 |
|------|------|
| 0 失败 + 达标率 > 60% + health ≥ 2.5 | **V4.0 Phase B 成功**，进入 Task 098 交付 |
| 0 失败但达标率 50-60% 或 health 2.0-2.5 | 有条件成功，记录限制，进入 Task 098 |
| ≥2 章失败或 health < 2.0 | **V4.0 Phase B 未完全成功**，评估是否需要额外修复 |
