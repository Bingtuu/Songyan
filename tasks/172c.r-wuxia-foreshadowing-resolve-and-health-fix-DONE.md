## 已交付

### 1. resolve 机制四层根因全修

| 层 | 根因 | 修复 |
|---|---|---|
| A. prompt 契约 | settlement prompt card 1.0.3 只演示 `plant`，LLM 不知道 resolve 该输出什么 | 新增 `prompts/cards/settlement_extractor/1.0.4.yaml`，`foreshadowing_updates` 增加 `resolve` 样例；规则 6 拆为 plant/resolve 两条；明确 `resolved_hooks` 仅作叙事摘要，不可替代 resolve 操作 |
| B. 替代出口 | `resolved_hooks` 自由文本被 LLM 当作回收出口，但不回写 DB | 在 prompt 中明确 `resolved_hooks` 与 `foreshadowing_updates` 的分工；保留该字段原有消费路径不变 |
| C. 事实源过滤 | `_load_current_foreshadowings` 用 `list_active()`，overdue 伏笔从 settlement prompt 消失 | 改为纳入 overdue（复用 `list_schedulable()` 语义），让逾期伏笔持续可见可 resolve；不动 `list_active()` 既有语义 |
| D. 同事务覆写 | `_update_continuity_tracking` 5.3 自动状态机走独立连接，把同事务内刚 resolve 的伏笔翻回 overdue | 跳过本单结算中已 resolve 的伏笔 id，以 settlement 内容为准 |

### 2. 静默丢弃点补日志

- `_build_foreshadowing_update` 遇到未知 operation 时输出 structlog warning；
- `apply_settlement` 遇到 resolve 缺 `foreshadowing_id` 时输出 structlog warning。

### 3. resolve 防幻觉校验

validate 阶段校验 resolve 的 `foreshadowing_id` 必须存在于当前可 resolve 集合（含 overdue），否则丢弃该条并记 warning，不阻塞整单 settlement。

### 4. continuity health 口径修复

`_find_overdue_foreshadowings` 改用 `ForeshadowingRepository.list_overdue_unresolved()`，口径与 vdim 冻结口径一致：`expected_resolve_chapter < up_to AND status != 'resolved'`，不再过滤 lifecycle 或 status 白名单。三层漏计（archived/dormant/active-overdue）全部纳入。

### 5. `get_unresolved_ratio` / `foreshadowing_pressure` 决策

**不改**。`foreshadowing_pressure` 全库无下游消费者，改动无收益；保留原口径并在本任务记录决策，避免未来误读。
