### 2.3 低分构成

当前 health 公式（Ch30 后 factor=0.5）：

```text
score = 10
      - diminishing(overdue) * 0.3 * 0.5
      - background_orphan * 0.1 * 0.5
      - technical_orphan * 0.05 * 0.5
```

Ch60 约等于：

```text
overdue 15 -> (10 + sqrt(5)) * 0.3 * 0.5 ≈ 1.84
background/technical orphan 11 -> ≈ 0.53
health ≈ 7.6
```

这与 V 维度尺度不一致：overdue 15 明显低于 sci-fi Ch60 约 120，不应单独把 health 拉到阻塞区。

## 3. 根因判断

1. **不是 CED 问题**：Ch60 consistency CED 0.19，优于 sci-fi 同章 0.38。
2. **不是 budget 问题**：budget peak < 1.0，无 context emergency halt。
3. **不是 floor 短窗口问题**：`foreshadowing_horizon_floor=48` 已使 Ch25/Ch50 overdue 为 0；Ch60 的 15 个 overdue 处于 sci-fi 同章尺度内。
4. **不是 state_mismatch 阻塞**：state_mismatch 已在 172c.s 降为 P3，不直接扣 health。
5. **根因是 health overdue 绝对扣分未按体裁/长窗口校准**：少量 backlog 在 V 门可接受，但 health 仍按绝对数量重扣。

## 6. 方案

新增字段：

```python
class ContinuityToleranceProfile(BaseModel):
    health_overdue_weight: float = 0.3
```

`ContinuityAuditor._compute_health_score()` 使用：

```python
weight = runtime_profile.continuity.health_overdue_weight if runtime_profile else 0.3
score -= diminishing(overdue) * weight * factor
```

wuxia 注册表：

```python
wuxia.continuity.health_overdue_weight = 0.15
```

按 Ch60 现场构成，health 从 7.6 提升到 ≥8；按 Ch99 现场构成，health 复算为 8.2。vdim overdue 门仍独立约束真实 backlog。
