## 目标

`variant generate` 对拒写 / 占位 / 复读类输出判失败，给作者真实可信的槽位状态与出口；明确重试策略与成本口径。不让垃圾槽以 `status=generated` + exit 0 + 照常计费的形式蒙混过关。

## 背景（冒烟实证，2026-11-11）

- **发现 3**：writer 面对空圣经产出 61 / 77 字拒写文本（「本章 canon 圣经为空…」「草稿槽位 2 —— 待填充」），仍标 `generated`、`stale_vs_canon=0`、exit 0、成本照记。空圣经主因已由 task 244 D2（圣经入选 R1 + 渲染去早退）消除。
- **发现 4**：圣经非空后重抽（confirm 13 条后），槽3 仍 46 字占位（¥0.0007），槽4 才是 1337 字真实正文（¥0.014）。**N=2 部分槽垃圾是常态风险**，与圣经是否为空无关。
- 影响面：`variant list` 把垃圾槽与真实稿并列展示，作者要靠肉眼逐槽甄别；`variant pick` 允许选中垃圾槽进入后续 W2 流程。

## 方案设计（决策点，待 owner 拍板）

1. **判定口径**：哪些信号算「拒写 / 占位」？
   - 候选信号：字数阈值（如 < N 字）、模板复读相似度（输出与 prompt 约束句高度重合）、「（空）」回显、显式拒写关键词（「无法完成」「cannot fulfill」等）。
   - 风险：误判把短章 / 实验性文体冤杀。阈值过松等于没判，过紧会误伤短草稿。
2. **判失败后的槽语义**：
   - 候选 A：沿用三态（generated / picked / archived），generated 槽加失败标记列（如 `quality_flag`），list/diff 露出。
   - 候选 B：生成时不落垃圾槽，直接同 slot 重试（作者看见的槽都是真实稿）。
   - 约束：M3 已接受的 variant 行生命周期是三态 + head 指针；新增状态值要动 pick / abandon / list 语义（tech-m3 边界，需 owner 认可）。
3. **重试策略**：
   - 同槽自动重试次数上限（成本口径：实测 ¥0.01–0.02 / 槽量级）；重试 prompt 是否注入「圣经有限也必须成稿」类指令；或完全不自动重试，只报告、由作者人工 `variant generate` 重抽。
   - task 226 已有「LLM 失败保留已写槽并报 stderr」的先例，重试语义要与之自洽。
4. **exit 码与计费**：N 槽全失败时 exit 码口径（B11：业务拒绝 = 2？）；判失败的 LLM 调用建议照常记 `llm_call_usage`（成本归因不丢）。
5. **措辞红线**：质量门通过 ≠ 「可发表」或「书写得好」（AGENTS.md）；最多表述为「可交付作者评审」。
