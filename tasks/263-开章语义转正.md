## 背景与根因

`chapter continue` 的目标 = 章宇宙第一个非 accepted 章（B1）。章宇宙只含已有 head/variant/version 的章——**想写的下一章不在宇宙里时，continue 返回「全部章已 accepted」（244 后的分文案），作者被迫走 SQL 铺 empty head 或 `variant generate --chapter N`（抽卡优先）**。dogfood 五轮里这是我每次都要绕的路；对真实作者这是产品里最后一处「需要懂数据库」的门槛。

## 方案（两候选，待 owner 拍板形态）

### 形态 A（推荐）：`chapter continue --chapter N` 显式目标

- continue 增加可选 `--chapter N`：**省略 = 现状自动 targeting 不变**；传入 = 显式目标章。
- N 不在章宇宙 → **命令内联铺 empty head（产品原生 seeding，替代 SQL）** → 走正常流程。
- N 已有 empty head → 正常开写；N 已有未确认工作稿（draft/picked）→ B1 前置② exit 2（与自动 targeting 完全一致，无自动重生成）。
- N 已 accepted → exit 2（提示已确认）；N 有 picked 未 accept 槽 → B1 前置① exit 2（提示先 accept/abandon）。
- 抽卡优先的作者仍走 `variant generate --chapter N`（不需要 head，不变）。
- 优点：不新增命令；「continue --chapter 3」心智与常见 CLI 一致；一步到位「开章+写」。

### 形态 B：`chapter open N` 独立子命令

- 只做 seeding（N 不在宇宙 → 建 empty head exit 0；已存在 → exit 0 幂等），写仍靠 continue。
- 优点：开章与续写语义分离；缺点：多一条薄命令，且「开完章还得再敲一次 continue」多一步。

### 共同口径（两形态一致）

- exit 码 B11 同形；不触发 settlement 副作用（head 行只在真正生成成功后才算数——empty head 本身无害，今日集成测试同款夹具）。
- dogfood/249 runbook 的 SQL seeding 段可删（验收时同步 `.tmp` 脚本，不入库）。
