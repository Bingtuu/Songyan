## 目标

`variant generate` 对拒写 / 占位 / 复读类输出判失败，给作者真实可信的槽位状态与出口；明确重试策略与成本口径。不让垃圾槽以 `status=generated` + exit 0 + 照常计费的形式蒙混过关。

## 背景（冒烟实证，2026-11-11）

- **发现 3**：writer 面对空圣经产出 61 / 77 字拒写文本（「本章 canon 圣经为空…」「草稿槽位 2 —— 待填充」），仍标 `generated`、`stale_vs_canon=0`、exit 0、成本照记。空圣经主因已由 task 244 D2（圣经入选 R1 + 渲染去早退）消除。
- **发现 4**：圣经非空后重抽（confirm 13 条后），槽3 仍 46 字占位（¥0.0007），槽4 才是 1337 字真实正文（¥0.014）。**N=2 部分槽垃圾是常态风险**，与圣经是否为空无关。
- 影响面：`variant list` 把垃圾槽与真实稿并列展示，作者要靠肉眼逐槽甄别；`variant pick` 允许选中垃圾槽进入后续 W2 流程。

## 方案设计（owner 拍板定稿，2026-11-11）

### P1 判定口径：字数兜底 + 硬信号

- **字数兜底**：输出 **< 100 字** 无条件判失败（章目标 3000 字，实证拒写产物 46–77 字、真实正文 ≥1337 字，误伤极低）。
- **硬信号**（命中即判失败，不受字数影响）：
  - 「（空）」或等价空回显（冒烟实证 `（空）` 出现在 B7 转调产出里）；
  - 显式拒写关键词：「无法完成」「cannot fulfill」「无法撰写」类（中英各一组小词表，保持薄封装）。
- 判定函数为纯函数，返回失败原因字符串或 None；**窄检查薄封装**，不加题材检查器。

### P2 槽语义 + 重试：重试 1 次后打标

- 拒写槽**自动同 slot 重试 1 次**：重试 prompt 注入坚持指令（「事实圣经内容有限也必须成稿，不得输出占位 / 拒写说明」类）。
- 重试后仍失败 → 槽照常落库，`status=generated` 不变（**不动 M3 三态生命周期**），新增可空列 `quality_flag` 标记失败原因；`variant list` 露出标记；`variant pick` 拒绝 quality_flag 非空的槽（exit 2 + 提示）。
- 与 task 226 先例自洽：LLM 层失败（超时 / 连接错）仍走「保留已写槽并报 stderr」路径，本门只管「调用成功但产出是垃圾」的形态。

### P3 exit 码：全败才 exit 2

- 至少一槽成功（含重试后成功）→ exit 0，stderr/输出摘要列出失败槽及原因；
- N 槽全部拒写（重试后仍失败）→ exit 2（B11 业务拒绝）+ stderr 说明。

### 默认假设（拍板时未单列，助手按以下口径执行）

- **计费**：判失败与重试的 LLM 调用照常记 `llm_call_usage`（成本归因不丢），重试成本实测约 ¥0.01 / 槽。
- **范围**：质量门只作用于 `variant generate` 抽卡路；**不扩**到 `run` / `chapter continue` 单稿路径（那条路径的拒写是另一个产品问题，如要做单列任务）。
- **措辞红线**：质量门通过 ≠ 「可发表」/「书写得好」（AGENTS.md）；CLI 文案只表述「已生成 / 槽位失败」级别。
